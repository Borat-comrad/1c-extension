## 2. Новая структура UI

Основной результат теперь выводится в следующем порядке:

1. Карточка детали.
2. Последнее КП по Эфес.
3. Закупочные цены.
4. История КП / предложений.
5. SAP-коды.
6. История поставок.
7. Данные рекламаций.
8. Дополнительные поля верхнего уровня, если они пришли.
9. Сырой JSON не добавляется в результат, поскольку `SHOW_RAW_1C_RESPONSE` выключен.

Закупка и предложение клиенту больше не объединяются в старый блок «Все цены».

## 3. Карточка детали

Карточка показывает:

- `КодЗапроса`;
- код, введённый пользователем;
- `КодКонечногоПроизводителя`;
- `Бренд`;
- `ПроизводительОборудования`;
- `Группа`;
- `РасширенноеНаименование`.

`null`, `undefined`, пустые строки, пустые массивы и пустые объекты отображаются как `нет данных`. Поля производителя оборудования и группы выводятся независимо, поэтому заполненная группа не скрывает пустой `ПроизводительОборудования`. Для расширенного наименования используется `white-space: pre-line`. Значения проходят через `escapeHtml`.

## 4. Разделение закупочных цен и КП

`getPurchaseEntries()` оставляет строки с числовой `ЦенаЗакупки`. Для старого контракта числовая `Цена` используется как fallback. Строковые числа не считаются закупочной ценой.

`getQuoteEntries()` оставляет строки, где заполнена `ДатаКП`, `НомерКП` или `ЦенаКП`. Поэтому строка может одновременно присутствовать в закупочной истории и истории КП, но в каждой зоне показывается соответствующий бизнес-смысл.

## 5. Последняя закупочная цена

`findLatestPurchaseEntry()` безопасно разбирает `ДатаКП` через `parseDateSafe()`.

- Если есть хотя бы одна валидная `ДатаКП`, выбирается самая свежая датированная закупочная строка.
- Если валидных дат нет, выбирается последний элемент массива закупочных строк.

В метрике показаны цена, валюта, контрагент и, при наличии, дата и номер КП.

## 6. Средняя закупочная цена

`calculateAveragePurchasePrice()`:

- учитывает только конечные значения типа `number`;
- не учитывает `null`, пустые строки, строковые числа и другие нечисловые значения;
- включает конкурентные строки;
- округляет результат до двух знаков;
- показывает `разные валюты`, если среди учтённых строк несколько непустых валют;
- показывает `нет данных` для валюты средней, если хотя бы у одной учтённой строки валюта не заполнена;
- не выполняет конвертацию валют.

## 7. Последнее КП по Эфес

`findLatestEfesQuote(entries, now)`:

- принимает фиксированную дату `now`, что позволяет делать устойчивые тесты;
- ищет клиентов без учёта регистра по маркерам `эфес`, `инбев эфес`, `аб инбев эфес`, `ab inbev efes`;
- требует валидную `ДатаКП`;
- требует числовую или непустую строковую `ЦенаКП`;
- выбирает самое свежее КП за календарные 12 месяцев до `now`;
- исключает будущие даты из списка исторических кандидатов;
- безопасно игнорирует некорректные даты.

Если КП в периоде нет, показывается сообщение `За последние 12 месяцев КП по Эфес не найдено`. Если более старое КП существует, оно выводится с пометкой о нахождении вне периода.

## 8. Поддержка старого JSON

Сохранены:

- `Цена` как fallback закупочной цены;
- `Валюта` как fallback валюты закупки;
- `ДанынеРекламаций`;
- SAP-коды в виде массива строк;
- произвольные объектные данные поставок, рекламаций и старых SAP-записей.

Старые ответы получают ту же новую структуру UI. При отсутствии полей нового контракта карточка показывает `нет данных`, не падая.

## 10. SAP-коды

Новый объектный формат выводится как отдельная карточка с полями `Клиент` и `SAP-код`.

Старая строка разбирается по последней запятой: левая часть становится клиентом, правая — SAP-кодом. Строка без запятой показывается целиком. Произвольные старые объекты, не содержащие `Клиент`/`SAPКод`, продолжают выводиться как пары ключ–значение.

## 11. Конкуренты

`isCompetitorEntry()` возвращает `true` только в двух случаях:

- `ЭтоКонкурент === true`;
- нормализованное `ТипКонтрагента` строго равно `конкурент`.

Такие закупки и карточки КП получают класс `competitor-price` и бейдж `Конкурент`. Блок Эфес также получает выделение, если выбранная запись конкурентная. Средняя закупочная цена включает эти строки.

## 12. Почему нет хардкода названий

Названия `КИП`, `Сталкер` и любые другие контрагенты не используются в логике классификации. Только 1С владеет бизнес-признаком конкурента, поэтому frontend не делает догадок по тексту названия. Это исключает ложные срабатывания при переименовании, совпадении названий или появлении новых конкурентов.

## 17. Состояние сырого JSON

Сырой JSON уже выключен в `popup.js`:

```js
const SHOW_RAW_1C_RESPONSE = false;
```

Renderer и CSS оставлены для диагностики. Если блок понадобится временно вернуть, значение можно изменить на:

```js
const SHOW_RAW_1C_RESPONSE = true;
```

Тестовые assertions сейчас требуют, чтобы `raw-json-block` отсутствовал в основном UI.
