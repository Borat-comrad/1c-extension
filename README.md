# gmail-1c-extension

Chrome Extension popup для получения и отображения истории цен из 1С по коду производителя.

> Диагностический ответ доступен в одном свёрнутом блоке `Сырой ответ 1С`. Форматированный JSON и сырой текст не дублируются.

## Демо-проверка расширения

1. Откройте Chrome на машине, где есть доступ к 1С-сервису.
2. Перейдите в `chrome://extensions`.
3. Включите `Developer mode`.
4. Нажмите `Load unpacked`.
5. Выберите папку проекта `gmail-1c-extension`.
6. Откройте popup расширения.
7. Введите тестовый код производителя:

```text
0-905-21-102-2
```

8. Введите логин и пароль 1С.
9. Нажмите `Получить историю цен`.

Ожидаемый результат в UI:

- показана карточка детали с кодами, брендом, производителем, группой и наименованием;
- отдельно показано последнее КП по Эфес;
- закупочные цены не смешиваются с ценами КП;
- показаны последняя закупочная цена и отдельные средние по каждой валюте;
- строки одного КП сгруппированы по номеру, а предложения поставщиков находятся внутри одной компактной карточки;
- длинные списки закупок, КП и SAP-кодов можно независимо раскрывать и сворачивать;
- SAP-коды, поставки и рекламации показаны человекочитаемо;
- диагностический ответ находится в закрытом по умолчанию `<details>`.

## Поиск по нескольким кодам

В поле `Код производителя` можно ввести несколько кодов через запятую:

```text
0-905-21-102-2, ABC-1000, XYZ-777
```

Пробел после запятой необязателен. Расширение очищает пробелы вокруг каждого кода, удаляет пустые элементы и повторяющиеся коды, сохраняя порядок первых вхождений.

За один поиск разрешено максимум 20 кодов. Если ввести больше, запросы в 1С не отправляются, а popup показывает ошибку:

```text
Слишком много кодов за один поиск. Максимум: 20.
```

При поиске нескольких кодов popup выполняет максимум 2 HTTP-запроса в 1С одновременно. Остальные коды ждут очереди. Ошибка одного кода не останавливает обработку остальных: результат каждого кода отображается в отдельной карточке с заголовком `Код: ...`. У каждого кода свой диагностический `<details>` и независимые кнопки раскрытия списков.

## Новый JSON-контракт 1С

Карточка детали поддерживает поля:

- `КодЗапроса`;
- `КодКонечногоПроизводителя`;
- `Бренд`;
- `ПроизводительОборудования`;
- `Группа`;
- `РасширенноеНаименование`.

Пустые значения отображаются как `нет данных`. Многострочное `РасширенноеНаименование` сохраняет переносы строк.

Массив `ИсторияЦен` разделяется на две бизнес-зоны:

- `Закупочные цены` использует числовые `ЦенаЗакупки` и `ВалютаЗакупки`. Для старого контракта поддерживается fallback на числовую `Цена` и `Валюта`.
- `История КП / предложений` использует `ДатаКП`, `НомерКП`, `Клиент`, `ЦенаКП`, `ВалютаКП`, `СтатусКП`, а также связанные данные закупки и поставщика.

Последняя закупочная цена выбирается по самой свежей валидной `ДатаКП`. Если на максимальную дату приходится несколько строк, выбирается последняя по исходному порядку массива. Если валидных дат нет, используется последняя закупочная строка. Исходный массив не сортируется.

Средние закупочные цены считаются отдельно для каждой нормализованной валюты. `руб.`, `руб`, `RUB` и `₽` объединяются в `Руб.`, а `EUR`, `eur` и `€` — в `EUR`. Остальные валюты группируются по нормализованному обозначению. Значения разных валют не складываются, конвертация и валютные курсы не используются. В расчёт входят только цены типа `number`, включая конкурентные.

История КП группируется по `НомерКП`. Если номера нет, используется резервный ключ `ДатаКП + Клиент`; полностью безымянные строки остаются отдельными. Внутри группы сохраняются все предложения и исходный порядок поставщиков. Группы с датой сортируются от новых к старым, затем показываются группы без валидной даты.

Статусы КП имеют семантические цвета: успешные — зелёные, промежуточные (включая `На рассмотрении`) — жёлтые, отрицательные — красные, неизвестные и пустые — нейтральные серые.

По умолчанию видны 4 закупочные строки, 3 группы КП и 5 SAP-кодов. Кнопки раскрытия работают без повторного запроса в 1С и независимо внутри каждого результата.

Блок `Последнее КП по Эфес` ищет клиента по маркерам `эфес`, `инбев эфес`, `аб инбев эфес` и `ab inbev efes` без учёта регистра. Среди КП с валидной датой и заполненной `ЦенаКП` выбирается самое свежее за последние 12 месяцев. Если в периоде ничего нет, UI сообщает об этом и при наличии показывает последнее найденное КП вне периода.

Конкурент определяется только по структурированным данным 1С:

- `ЭтоКонкурент === true`;
- либо `ТипКонтрагента` после удаления пробелов и приведения к нижнему регистру равно `конкурент`.

Конкурентные закупки и КП получают отдельное выделение и бейдж `Конкурент`. Названия `КИП` и `Сталкер` не хардкодятся и сами по себе не влияют на классификацию.

`СписокСапКодов` поддерживает оба формата:

- новый объект `{ "Клиент": "...", "SAPКод": "..." }`;
- старая строка `"Клиент, SAP-код"`, разбираемая по последней запятой.

Поддерживаются оба варианта поля рекламаций: `ДанныеРекламаций` и историческое `ДанынеРекламаций`.

## Ограничения

- Если 1С не заполняет `ДатаКП`, блок последнего КП не сможет определить запись и период.
- Если 1С не заполняет `ЦенаКП`, frontend не сможет показать цену КП или выбрать эту строку для блока Эфес.
- Если 1С не заполняет валюту, UI покажет `нет данных`.
- Если 1С не передаёт `ЭтоКонкурент` или `ТипКонтрагента`, frontend не угадывает конкурента по названию.
- Средние разных валют рассчитываются независимо; конвертация валют не выполняется.
- Диагностический блок показывает один вариант тела ответа: форматированный JSON, если парсинг успешен, иначе сырой текст.
